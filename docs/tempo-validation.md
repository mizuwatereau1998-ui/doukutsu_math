# テンポ調整の検証記録

8シード（1, 42, 917, 305, 17, 81, 291, 832）を固定ステップ1/120秒で実行。算数は正解の道を選び、アクションは既存の物理に対してジャンプ・下降を操作する。速度や衝突判定の無効化は行わない。全ケースでミス0。実機の操作感の評価とは別の、成立する回避経路と頻度の確認。

## 原因と変更

変更前の計測では候補の不採用は0回だった。主な空白は、10秒の問題、問題後に画面外から再接近する約4秒の待ち、群れ・急降下の遅い解禁、先行障害物の後ろへ候補を積み続ける配置方法によるものだった。

変更後は、6秒の問題、右側から最低2秒の接近余裕を持つ配置、3秒先までを目安にしたキュー制限、A〜Fの連続パターン、通常→急降下→群れの導入を使う。候補不成立時には別候補を最大3回、さらに単独の安全候補まで検証する。検証は省略しない。問題前に接近中の障害物を消さず、通過後に開始する。

## 再実行

```sh
npm test
node tests/tempo.mjs
```

`tests/tempo.mjs` はJSON Lines形式で上記の数値と各問題の開始時刻・判断時間を出力する。テストでは最初の30秒で全3種類が遭遇すること、実遭遇数の下限、連続配置、6〜2秒の判断時間を確認する。通常問題と特別問題の時間・タイムアップ、既存の記録保存や操作も検証。全53項目。

150mは出題の基準であり、6秒の問題表示と連続アクションを両立するため、実際の開始距離が節目を越えることがある。問題終了後最低5.5秒、最低4個の障害物を配置するアクション区間を挟む。障害物が残る場合はさらに通過を待つ。
