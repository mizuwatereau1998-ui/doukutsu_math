# ポップンの大脱走！

**かけて、わって、とびこえて。** 青いゼリーのポップンと走る、算数学習 × エンドレス逃走アクションの試作版です。

HTML / CSS / JavaScript だけで動きます。パッケージのインストール、ビルド、アカウント、APIキーは不要です。

## まずあそぶ

1. リポジトリのファイルをまとめてダウンロードし、ZIPの場合は展開します。
2. **`index.html` をブラウザで開きます。** 他のファイルは同じフォルダ構成のままにしてください。
3. 小3・小4を選び、「さあ、にげよう！」を押します。

開発時は、リポジトリのフォルダで次のコマンドを実行しても起動できます（Python 3が必要）。

```sh
python3 -m http.server 8000
```

ブラウザで `http://localhost:8000` を開きます。終了はターミナルで `Ctrl+C`。Node.jsがある環境では `npm start` でも起動できます。`npm install` は不要です。

スマホは **横向き** にしてください。縦向きにするとゲームを一時停止します。別タブやホーム画面に移ったときも自動で停止します。

## 操作

| 操作 | PC | スマホ |
| --- | --- | --- |
| ジャンプ・上の道へ | 上矢印キー ↑ | 上スワイプ |
| 下の道へ | 下矢印キー ↓ | 下スワイプ |
| 一時停止・再開 | Esc または右上の Ⅱ | 右上の Ⅱ |
| 効果音の切り替え | ページ右上の ♪ | ページ右上の ♪ |

- 自動で走るので、左右の操作はありません。
- 通常時、下段で ↑ を押すと **ジャンプして上段に乗ります**。上段で ↑ を押すとその場でジャンプします。空中での連続ジャンプはできません。
- 穴はジャンプ、上段に垂れ下がる鍾乳石は ↓ で回避します。
- 問題中は ↑ / ↓ で隣の道へ1段ずつ移動します。3択の最上段へは ↑ を2回。通常走行では1段ずつジャンプして上がるため、着地してから次の ↑ を押します。キーの押しっぱなしではなく、1回ずつ押してください。
- 短いスワイプでも反応します。1スワイプにつき1段だけ移動します。

## ゲームのルール

- 5回ミスすると追手につかまり、結果画面へ進みます。途中のミスではゲームは止まりません。
- ミス直後は1.2秒間の無敵時間があり、近くの障害物も除かれます。
- 出題は150m、300m、450m…の節目が基準です。表示中は重ねず、通過した複数の節目は1問にまとめます。
- 問題終了後は最低5.5秒のアクション区間を挟みます。連続パターンが残っている場合は、最後の障害物が通過する時間と安全区間を確保してから次問を始めます。そのため、序盤の6秒問題などで次の節目を通過した場合、実際の出題距離は150mより長くなります。出題が近づくと新しい配置を止め、接近中の障害物は消さずに通過を待ちます。終了直後0.6秒は安全区間です。
- 最初の数秒は猶予があり、その後は単独と2連続の配置が登場します。序盤から3連続も現れ、進むほど複雑な配置の割合が増えます。
- 開始直後から通常飛行のコウモリが飛んできます。最初の障害物パターンには必ず登場し、その後もコウモリなしの配置が続かないようにしています。最初の30秒で通常・急降下・群れの3種類を順に体験できる導入を入れています。急降下前は翼を構えて金色の小さな合図を出し、斜め下に飛び込みます。群れは高さが交互に変わる2〜3匹が時間差で飛んできます。下段の低いコウモリはジャンプ、上段の高いコウモリは下降で回避します。羽先は当たり判定に含めず、胴体に触れると1ミス。無敵時間も適用します。
- 式が出てから分岐に着くまでに、答えの道を選びます。制限時間終了時の道で自動判定します。問題中は穴や鍾乳石は出ません。
- 通常問題は、正解でそのまま、不正解で1段階後退します。
- 金色にきらめく問題は、正解すると追手から1段階離れます。基本は3問ごと、危険なときは早めに登場します。追手から最も離れているときには出ません。
- 900m以降は3択になり、通常のアクションも3段のまま維持します。80m手前から最上段の足場が徐々に見え始めます。
- 速度は230px/秒から最大500px/秒へ滑らかに上がります。判断時間は最初の6秒から、3,600mで最短2秒まで短くなります。
- 最高記録は **小3・小4別々** にブラウザのlocalStorageへ、ゲームオーバー時に保存します。ブラウザやアクセス先を変えると別の記録になります。保存が制限されている場合もプレイできます。

### 出題範囲

| 学年 | かけ算 | わり算 | 小数 |
| --- | --- | --- | --- |
| 小3 | 2〜9の九九 | 九九を使う、割り切れるわり算 | 小数第1位までのたし算・ひき算 |
| 小4 | 2桁 × 1〜2桁 | 最大3桁 ÷ 1〜2桁、割り切れるもの | 小数第2位までのたし算・ひき算 |

3種類からランダムに出題します。小数は10倍・100倍した整数で扱い、誤差のある答えや選択肢の重複を防いでいます。余り、分数、筆算の入力は試作版には含みません。

## 難易度を変える

**`js/config.js` の `CONFIG`** に主な設定をまとめています。値を変更し、ブラウザを再読み込みすると反映されます。

| 定数 | 初期値 | 内容 |
| --- | --- | --- |
| `startSpeed` / `maxSpeed` | 230 / 500 | 最初と最大の走行速度（px/秒） |
| `speedGrowthDistance` | 2000 | 速度の上がり方。大きいほど緩やか |
| `questionIntervalMeters` | 150 | 出題の節目となる距離間隔（m） |
| `questionRestSeconds` | 5.5 | 問題終了から次問までに挟む最低アクション時間（秒） |
| `questionSafetyMeters` | 35 | 次の出題直前に障害物を除く距離（m） |
| `questionSafetySeconds` | 0.6 | 問題前後の安全時間（秒） |
| `batStartDistance` | 0 | コウモリが登場し始める距離（m） |
| `batChanceMax` | 0.8 | 後半のコウモリの最大生成確率 |
| `batSpeedFactor` | 1.08 | コウモリの接近速度倍率 |
| `batMaxDryPatterns` | 1 | コウモリなしの配置を許す最大連続数。最初の配置にも必ず登場 |
| `obstacleMinEncounterGap` | 1.25 | 前の障害物通過から次の接近までの最低間隔（秒） |
| `obstacleInitialDelay` | 0.6 | 最初の候補を生成するまでの時間。右端から接近する時間も猶予になる |
| `obstacleReactionSeconds` | 0.3 | ジャンプ・下降時間に加えて確保する操作の余裕（秒） |
| `patternDoubleChance` | 0.9 | 2連続の基本確率 |
| `patternTripleDistance` / `patternTripleChanceMax` | 0 / 0.55 | 3連続が増え始める距離と最大確率 |
| `batChanceStart` / `batChanceGrowthMeters` | 0.6 / 3000 | コウモリの初期確率と確率の増加速度 |
| `batDiveDistance` / `batFlockDistance` | 0 / 0 | 急降下型・群れ型が解禁される距離 |
| `batDiveChance` / `batFlockChance` | 0.35 / 0.35 | コウモリを選んだ場合の各種類の確率 |
| `batDiveLeadSeconds` / `batDiveWarnSeconds` / `batDiveSeconds` | 1.65 / 0.45 / 0.65 | 接近時間で決める急降下開始位置・予備動作・下降時間 |
| `questionTimeMax` / `questionTimeMin` | 6 / 2 | 最長・最短の判断時間（秒） |
| `shortestTimeDistance` | 3600 | 判断時間が最短になる距離（m） |

| `obstacleIntervalStart` / `obstacleIntervalEnd` | 0.7 / 0.35 | 序盤・後半のパターン生成候補の間隔（秒）。最大0.35秒のばらつきが加わる。キューが3秒先まである間は追加しない |
| `specialEvery` | 3 | 特別問題が出る基本の問題数間隔 |
| `dangerSpecialAt` | 3 | 特別問題を早めるミス数 |

## ポップンの11枚の画像アニメーション

`assets/characters/` の透過PNG（512×512px）を使用します。`js/config.js` の `useCharacterImages` は `true` です。旧 `pop_idle.png` / `pop_correct.png` / `pop_chain*.png` の設定は廃止しました。

| 状態 | ファイル | 切り替え |
| --- | --- | --- |
| 走行 | `popn_run_01.png`〜`popn_run_04.png` | 01→02→03→04の循環。開始時10fps、最高速度で16fps |
| 上昇 | `popn_jump_01.png` / `popn_jump_02.png` | 上昇の初期は01、頂点に近づくと02 |
| 下降 | `popn_fall.png` | 下段への移動・頂点からの下降 |
| 転倒 | `popn_stumble_01.png` / `popn_stumble_02.png` | 既存の0.48秒の前半01、後半02 |
| 焦り | `popn_panic.png` | 追手との距離が残り2段階以下。走行の弾み・傾きを維持 |
| 喜び | `popn_happy.png` | 正解後0.65秒。キラキラ問題でも同じ |

優先順位は転倒→上昇/下降→喜び→焦り→走行。算数の上下移動も実際の高さに合わせて上昇/下降画像を選びます。喜びの表示中も通常通り操作でき、ジャンプや下降を優先します。表示用の時間計算はゲームの経過時間と実際の移動距離を使い、一時停止で止まり、新規プレイでリセットします。物理・衝突・難易度・出題・記録のルールは変えていません。

透明余白を含む元画像を共通倍率で描き、画像の不透明部分ごとに拡大・縮小しません。共通の足元 `(256, 470)` を基準に、画像ごとの足元の数px差を補正しています。転倒時の低い姿勢や喜びの腕の広がりはポーズとして維持します。走行時の追加の上下動は最大2px、伸縮は約1.8%、傾きも控えめにし、画像の動きと重なりすぎないようにしています。着地の軽い潰れも足元を基準に適用します。

後から調整する場合は `js/config.js` の `characterAnimation` を変更します。

- `runFps` / `runMaxFps`: 通常・高速走行のコマ数
- `jumpApexVelocity`: 上昇画像01→02へ切り替える速度の閾値
- `happySeconds` / `panicRemaining` / `stumbleFirstFraction`: 喜びの表示秒数、焦りの段階、転倒画像の切り替え位置
- `heightInRadii` / `scale`: 全体の表示サイズ（当たり判定は変えない）
- `sourceFootX` / `sourceFootY` / `sourceBodyHeight`: 元画像の共通の足元と基準高さ
- `offsetX` / `offsetY`: ゲーム座標での全体表示位置
- `frames.<画像キー>` の `footX` / `footY` / `offsetX` / `offsetY` / `scale`: 各画像の足元・位置・倍率の補正。省略値は共通値を使用
- `runBouncePixels` / `runSquash` / `runLean` / `runTilt` / `landingSquash`: 走行・着地の追加変形
- `airMotionStrength` / `stumbleMotionStrength`: 空中・転倒画像への既存変形の強さ

`stumbleSeconds`（0.48）と `smileTimerSeconds`（1.7）は既存ゲーム内部のタイマーに合わせた参照値です。表示だけを調整する場合は、内部タイマーを変えず上記の割合・表示秒数を調整してください。

画像はタイトル表示時に先読み・デコードし、11枚の読み込み結果が揃ってから開始できます。1枚でも失敗した場合や8秒の読み込み期限を過ぎた場合は、全状態でCanvasの仮キャラクターを使い、コマごとにPNGと仮描画が交互に出る現象を避けます。`useCharacterImages: false` でCanvas描画に戻せます。相対パスなのでGitHub Pagesのリポジトリ配下でも動きます。

ブラウザ検証はHTTPサーバー起動後の `python3 tests/browser_animation.py`。全11枚、実際の操作・正解・転倒イベントからの切り替え、スマホ横向き、画像の一部/全部の読み込み失敗を確認します。確認用の画像一覧は `/tmp/poppun-animation-gallery.png`、スマホ画面は `/tmp/poppun-animation-mobile.png` に出力します。

## くらやみのスライムの8枚の画像アニメーション

`assets/monsters/` の512×512px透過PNGを使用します。`js/config.js` の `useMonsterImages` は `true` です。主人公の画像設定・フレーム選択は変更していません。

| 状態 | ファイル | 切り替え |
| --- | --- | --- |
| `chase` 通常追跡 | `chase_run_01.png`〜`chase_run_04.png` | 01→02→03→04のループ。速度に応じ9〜14fps |
| `threat` 威嚇 | `chase_threat_01.png` / `chase_threat_02.png` | 残り2段階以下。01↔02を7〜10fpsでループ |
| `capture` 捕獲 | `chase_capture_01.png` / `chase_capture_02.png` | 最後のミスで01→02、合計0.8秒で結果表示 |

優先順位はcapture→threat→chase。回復して残り3段階以上になるとchaseへ戻ります。通常・威嚇のフレーム時計は実際の経過時間と走行距離から計算し、一時停止で止まります。状態変更時は先頭のコマから始め、威嚇の前傾は0.18秒かけて加えます。従来の追手の位置（ミス数による接近）、表示倍率の増加、ミス直後の小さな突進は維持しています。

元画像の足元 `(256,465)` を基準に、2px程度の画像差を個別補正します。不透明部分の高さごとに拡大・縮小せず共通の倍率を使うので、低い通常ポーズや大きく口を開く捕獲ポーズがそのまま表現されます。共通幅は260pxを基準とし、既存の追手倍率を掛けます。下端を最下段の地面に合わせ、伸縮と小さな傾きを足元中心に加えます。威嚇は伸縮を強め、少し前へ乗り出します。

追手の追加倍率は、2段ステージで **1.5倍**、900m以降の3段ステージで **2.2倍** です。基準幅260pxと従来のミス数による倍率に重ねます。ミス0の通常画像では、体の見えている高さは約210px→約308px（画像のポーズにより変動）になり、下段から中段、強化後は上段まで届く大きさになります。

通常プレイで900mを跨ぐと、**0.85秒**かけて完成後のサイズへ滑らかに移行します。最初の短い区間でぷるんと膨らみ、少し明るくなって小さく横揺れします。演出は追手だけに適用し、ポップン・背景・算数UIを揺らしたり、ゲームを止めたりしません。強化は1プレイにつき一度だけ。一時停止中は進行せず、回復でミス数が減っても強化後サイズは維持し、新しいプレイでは2段用サイズへ戻ります。900m以上からの開発用開始では、演出を挟まず強化後サイズを表示します。

拡大分は足元を基準に配置し、顔が画面左へ隠れすぎないよう調整しています。画像の変形後の外接矩形を計算し、通常追跡・威嚇中はポップンの進路より左に収めます（右端はプレイヤー座標の30px手前、さらに12pxの余裕）。障害物や答えの道を隠すためのクリップではなく、描画位置だけの補正です。追跡位置・ミス数・当たり判定は変更しません。捕獲時にはこの制限を外して、従来どおりポップンへ飛び出します。

描画上は「2段の通常追跡」「強化中」「3段の強化後追跡」を持ちます。画像の状態は従来どおりchase/threat/captureであり、強化中でも威嚇・捕獲の画像を優先します。捕獲中は追加の膨張・明滅・小さな揺れを抑えます。視差効果を減らす設定では、サイズの滑らかな移行だけを行います。画像失敗時のCanvas代替にも強化後サイズを適用します。

ゲームオーバーの判定と距離・正解数・最高記録の確定は最後のミス時に従来通り即座に行います。ゲーム本体は `over` のまま停止し、描画専用の時計で前方へ90px飛び出して捕獲01→02を再生します。0.8秒後に結果パネルを開くだけなので、演出中に距離やスコアは増えず、保存も重複しません。新規プレイや学年選択へ移った場合は前の捕獲演出を持ち越しません。視差効果を減らす設定では大きな移動・伸縮を抑え、2枚の切り替えと結果表示は維持します。

調整値は `js/config.js` の `monsterAnimation` にまとめています。

- `chaseFps` / `chaseMaxFps`、`threatFps` / `threatMaxFps`: 通常・高速時のコマ数
- `threatRemaining` / `transitionSeconds`: 威嚇になる残り段階と前傾の移行時間
- `captureSeconds` / `captureFirstFraction`: 捕獲全体の秒数（推奨0.6〜1.0）と01の表示割合
- `captureAdvance` / `captureLungeSeconds`: 捕獲時に前進する距離と前進時間
- `width` / `scale` / `offsetX` / `offsetY` / `flipX`: 追手画像の基準幅、全体倍率、位置、左右反転
- `twoLaneScale` / `threeLaneScale`: 2段・3段用の追加倍率（1.5 / 2.2）
- `levelUpSeconds` / `levelUpPulse` / `levelUpSquash`: 強化時間、瞬間的な膨張率、うねりの強さ
- `levelUpShakePixels` / `levelUpShakeCycles` / `levelUpBrightness`: 追手自身の横揺れ幅・回数、明るさの増加量
- `growthAnchorRatio` / `frontClearance` / `frontPadding`: 拡大の基準、進路を空ける距離、変形時の余裕
- `canvasFootY`: Canvas代替描画の足元基準
- `sourceWidth` / `sourceFootX` / `sourceFootY`: 元画像の共通の幅と足元基準
- `frames.<画像キー>` の `footX` / `footY` / `offsetX` / `offsetY` / `scale`: 画像ごとの補正
- `chaseSquash` / `threatSquash`、`chaseBounce` / `threatBounce`、`chaseTilt` / `threatTilt` / `threatLean`: 伸縮、上下動、傾き、威嚇の前傾

画像は主人公と別の保存先・読み込み状態で並列に先読みし、開始時は両方の完了を待ちます。相対パスなのでGitHub Pagesでも使用できます。追手画像が1枚でも失敗、または8秒の期限を超えた場合は、追手だけを既存のCanvas描画へ戻します。主人公のPNGには影響しません。代替描画でも捕獲後に結果画面へ進みます。`useMonsterImages: false` でも追手をCanvasへ戻せます。

検証はHTTPサーバー起動後の `python3 tests/browser_monster.py`。通常4枚・威嚇2枚の順序、回復、捕獲01→02→結果、記録の1回保存と演出中の値の不変、新規プレイへの持ち越し、スマホ表示、追手の一部/全画像の失敗を確認します。ゲーム・物理・出題・障害物・入力のソースはこの改修で変更していません。大型化と900mでの強化演出は `python3 tests/browser_monster_growth.py` で、2段/3段サイズ・一度だけの強化・一時停止・UIの視認性・スマホ・代替描画を検証できます。

## 走行アニメーションと背景

`js/renderer.js` の `Visual` に見た目の設定をまとめています。`stride` は1回弾むまでに進む距離（px）で、小さくすると弾むテンポが速くなります。実際の走行距離から周期を求めるため、ゲームの加速・停止にそのまま連動します。着地の潰れ、前傾、ジャンプ・下降・転倒の姿勢は図形とPNGに共通です。端末で「視差効果を減らす」等を有効にすると、追加の弾みや速度線を抑えます。

以前は足場が画面上に固定され、模様・結晶・支柱だけが別々に流れていたため、動く歩道のように見えていました。現在は岩盤と装飾を同じ世界座標から描き、穴の位置も含めて一体で移動します。`Visual.parallax` の遠景・中景・近景・足元・最前景の倍率で奥行きを表現しています。カメラの基準位置と衝突面は従来通りで、描画の弾みや傾きは物理計算には反映しません。

追手も距離に連動して腕と足を交互に振り、前傾して上下に弾みます。ミスが増えると振幅や表情が強まり、ミス直後は短い突進を行います。追跡ゲージやゲームオーバーの判定には使わない描画上の動きです。コウモリの羽ばたきと上下の揺れもCanvasで描き、上下の揺れは当たり判定にも共通の座標を使っています。

## 常設3段とクモ

900m（`threeChoiceDistance`）で解放された最上段は、そのプレイ中は常設されます。通常時も上下で隣の段へ移動でき、最上段で↑はその場のジャンプになります。算数が終わっても最上段を維持します。

クモは天井で待機し、糸の発光と体の揺れ（初期値0.5秒）の後、0.28秒で中段または最下段へ降下します。1.3秒停止後、0.45秒で戻ります。**糸・脚先には衝突判定がなく、本体だけ**が降下中・停止中・上昇中の実際の位置で判定されます。

調整箇所は `js/config.js` の `advancedBands` の `spider` と `spiderMaxDryPatterns`（1：クモなしの配置が続くのを防ぐ）、`spiderLeadSeconds`（1.8）、`spiderWarningSeconds`（0.5）、`spiderDropSeconds`（0.28）、`spiderHoldSeconds`（1.3）、`spiderRiseSeconds`（0.45）、`spiderRadius`（18）です。最上段へのコウモリ・クモ・穴や鍾乳石を組み合わせ、同じ物理シミュレーションで経路が成立する配置だけ採用します。

プレイでは、900m手前の足場の見え方、900m以降にジャンプ・下降で全段へ移動できること、クモの合図と本体の動き、糸を横切っても無傷であることを確認してください。実機のiPhone/Androidは引き続き未確認です。

## 3段構成と2000m以降の高難度配置

900mから3段構成になります。上段・中段の穴はすべてトゲに変更し、最下段の穴は維持しています。トゲは足場の上の三角形の列です。Canvas描画と衝突判定は同じ三角形を使い、ポップン本体の円と接触するかを調べます。段番号だけでは判定せず、ジャンプ中や別の段へ下降中でも実際の位置で判定します。先端より十分高く跳べば安全です。

3段専用配置は、2段を同時にふさぐ波で構成します。安全段の列には「上→中→下→中→上」「下→中→上→下→中」「中→上→下→中→上」「上→下→中→下→上」があり、距離帯に応じて先頭の2〜5波を使います。コウモリ・クモ・トゲ・最下段の穴を組み合わせます。2000m以降は高い位置のコウモリも併用し、上段にとどまって跳ぶだけの抜け道を抑えます。大きいコウモリは見える本体の幅と判定幅を一致させています。

| 距離帯 | 波数 | 配置の狙い |
| --- | ---: | --- |
| 900〜1500m | 2 | 2段封鎖と上下移動への適応 |
| 1500〜2000m | 3 | 安全段の連続切り替えとクモ連携 |
| 2000〜3000m | 4 | トゲ・クモ・コウモリの複合、少ない入力で抜ける候補を排除 |
| 3000m以降 | 5 | 着地を待たず空中で次の移動へつなげる、短い間隔の連続操作 |

間隔は一律ではありません。`Physics`で1段上昇・2段上昇・1段下降・2段下降を試走し、必要時間に余裕と障害物通過時間を加えます。2段上昇では中間段への着地と2回目の入力を待ちます。3000m以降は最後の移動先に体が到達した時点を基準にし、最後の着地を必ず待つ方式より詰めます。クモの予告・降下・停止・上昇は維持し、糸・脚には当たり判定を付けていません。

生成時には待機・上下操作の複数経路を探索し、少ない入力で通れる経路を優先して探します。入力間隔は0.18秒以上（探索の刻みでは通常0.2秒）確保します。2000m以降は4入力、3000m以降は5入力に満たない経路で抜ける候補を捨てます。不採用時も波数と高難度の構成を維持し、別の安全段の列と到達時刻を試します。生成失敗・安全性不採用・簡単すぎる不採用は別々に集計します。

主な調整値は `js/config.js` にまとめています。

- `advancedBands`: 距離の境界、波数、余裕時間、クモ率、空中封鎖、入力数の下限、着地を待たない移動の有効化
- `advancedSafeSequences`: 安全段の列（0=上、1=中、2=下）
- `transitionInputSeconds` / `transitionClearanceSeconds` / `transitionArrivalInset`: 連続入力の間隔、通過の余裕、空中での到達判定
- `advancedJumpRepeatSeconds`: 同じ段でジャンプを繰り返すときの最低周期
- `spikeHeight` / `spikePitch` / `spikeBodyRadius`: トゲの高さ・間隔・本体判定の半径
- `advancedGuardOffset` / `advancedGuardWidth`: 高いコウモリの高さ・本体幅
- `advancedAttempts` / `advancedRetryDelay`: 再抽選回数と到達時刻の延期量
- `routeDecisionSeconds` / `routeMaxStates` / `routeMaxSeconds`: 経路探索の刻み・保持状態数・時間上限

検証は `node tests/difficulty.mjs`（従来の `node tests/advanced-patterns.mjs` も同じ検証を実行）。入力数、操作密度、同じ段だけで抜けられる割合、実際の同時封鎖、種類別件数と生成失敗を調べます。[変更前後の難易度検証](docs/chaos-validation.md) に記録しています。算数・回復・5ミス終了・操作・ポップンと追手のアニメーションは従来通りです。HTTPサーバー起動後の `python3 tests/browser_pressure.py` では、3000mからブラウザ本来の描画ループと上下キーイベントで連続走行を確認できます。

## 開発用の距離開始モード

公開ページまたは開発用HTTPページのURL末尾に `?devStart=900` / `?devStart=1500` / `?devStart=2000` / `?devStart=3000` を付け、通常の開始ボタンを押すと、その距離から始まります。通常画面に追加の選択ボタンはありません。開始時のメッセージでテスト走行であることを示します。

## 洞窟の画像アセット

トゲ・鍾乳石・コウモリ・クモは透過PNGで描画します。元画像のまま保存し、Canvasの切り出しで透明余白とコマごとの本体位置を補正しています。

| 用途 | 画像パス |
| --- | --- |
| 地面の五本岩スパイク | `assets/stage/cave_spikes.png` |
| 紫水晶の鍾乳石 | `assets/stage/amethyst_stalactite.png` |
| コウモリ横3コマ | `assets/enemies/purple_bat_sheet.png` |
| クモ横3コマ | `assets/enemies/cave_spider_sheet.png` |

調整は `js/config.js` の `caveAssets`（画像パス）と `caveVisuals`（表示設定）で行います。

- `spikes.source`：切り出し範囲。`groupWidth`：画像を繰り返す幅の目安。`offsetY`：接地位置。表示の高さは既存の `spikeHeight` に合わせます。
- `stalactite.source`：中央の長い岩の切り出し範囲。`roofY`：天井の接続位置。`widthPadding`：危険範囲に対する左右合計の余白。`offsetY`：上下補正。先端は既存の危険範囲の下端に合わせます。
- `bat.fps`：10fps。`sequence`：0→1→2→1。`frames` の `source` / `anchor`：切り出し範囲と本体中心の元画像座標。`bodyWidth`・`scale`・`offsetX/Y`：表示倍率と位置補正。通常・急降下・群れ・大型のすべてに適用します。
- `spider.frames`：上・中・下のコマと本体中心。`threadRoofY`：糸の天井側の接続位置。`bodyWidth/Height`・`scale`・`offsetX/Y`：表示倍率と位置補正。既存の降下・停止・上昇の本体座標に合わせ、降下率でコマを切り替えます。両方の着地点に対応し、糸は天井からCanvasで補います。

画像は開始前にロードし、読み込み失敗時は従来の図形描画に戻ります。羽ばたきは障害物の経過時間を使い、一時停止中は停止します。当たり判定・出現頻度・移動速度・算数・操作・ポップンと追手のアニメーションは従来の処理を維持しています。最下段の穴も維持しています。
